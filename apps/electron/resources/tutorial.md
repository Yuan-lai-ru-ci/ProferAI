# Profer 用户指南

> 更新于 2026-08-19。本指南按当前桌面端界面编写；功能入口和模型支持会持续调整。若本文与实际界面、版本说明不一致，请以当前客户端为准。

## 先完成一次真实任务

Profer 的重点不是多聊几句，而是把一件具体的事交给合适的模式完成。第一次使用时，建议按下面顺序走一遍：

1. 打开 **设置 → 模型配置**，确认已有可用模型；若团队为你提供了官方模型池，直接选择其中的模型即可。
2. 切换到 **Agent**，选择或新建一个工作区和会话。
3. 在输入工具栏确认模型、Agent 内核、权限模式和预设。
4. 给 Agent 一个范围清晰、能验收的任务。
5. 查看它读取的文件、执行过程和最终产物；必要时在权限请求处批准或拒绝。

可以先用下面的任务测试环境：

> 在当前工作区创建 `hello.md`，写一段项目介绍，包含项目名称、目标和技术栈。完成后告诉我文件路径，并检查文件内容是否存在。

只想问问题、改写文字或讨论方案时使用 **Chat**；希望 Profer 读取文件、修改项目、执行命令或连续完成多个步骤时使用 **Agent**。

教程入口在 **设置 → 体验 → Profer 教程**。教程会以独立标签页打开，不会覆盖正在进行的会话。

## 一、先认识界面

### Chat 和 Agent

**Chat** 是对话模式，适合问答、翻译、总结、润色、头脑风暴和轻量分析。它可以使用当前启用的 Chat 工具，例如联网搜索或 GPT Image，但主要交互仍是“输入问题，获得回答”。

**Agent** 是执行模式。Agent 会在工作区中调用文件读写、命令、搜索、预览、Skills、MCP 和产品内置工具，把目标拆成步骤，并根据每一步的结果继续推进。它适合开发、整理资料、生成文档、批量处理文件和需要验证结果的长任务。

两种模式的会话和可用模型会因渠道、协议、当前 Agent 内核而不同。模型选择器中没有预期模型时，先确认当前处于 Chat 还是 Agent、渠道是否启用，以及模型是否支持当前内核。

### 左侧栏、标签和右侧面板

左侧栏主要包含：

- Chat 和 Agent 会话；
- Agent 工作区及其会话；
- **规划中心**：Todo、日程和定时任务；
- **Agent 技能**：Skills、MCP、记忆和预设；
- 账户、工作区和设置入口。

一个工作区可以包含多个 Agent 会话。建议让一个会话围绕一个目标推进；跨阶段仍要复用的信息写入工作区文件或长期记忆，而不是把所有事情堆进一条无限变长的聊天记录。

主区域顶部可以同时打开 Chat、Agent、文件预览和教程等标签。Agent 标签右侧通常可打开：

- **文件面板**：查看会话文件、工作区文件和改动；
- **受管浏览器**：供 Agent 在受控边界内操作网页；
- **预览**：查看 Agent 修改后的 Markdown、代码或其他支持的文件。

文件面板和浏览器按会话关联。切换标签后，先确认正在查看的是哪个会话的内容。

## 二、首次启动、登录和模型

### 首次启动与备份迁移

首次启动会进入欢迎和环境检测。Windows 上让 Agent 执行命令通常需要可用的 **Git Bash 或 WSL**；按检测页提示安装并重新检测。其他系统的要求以当前安装包和检测结果为准。

换机或恢复环境时，可在 **设置 → 数据管理** 导出或导入备份。个人备份可能含 API Key 等敏感信息，只应保存到可信位置，不要通过公开聊天、网盘链接或不可信设备传播。

### 个人工作区和团队账号

Profer 可以仅使用本地工作区，也可以登录团队账号：

- **个人工作区**：适合个人项目、笔记和本地文件，数据主要保存在本机；
- **团队工作区**：适合共享文件、共享记忆、团队 Skills 和协作项目，需要登录并取得对应工作区权限。

本地功能不以登录为前提；团队协作、订阅/额度、开放 API 和登录设备管理则取决于账号与管理员授予的权限。

### 配置或选择模型

进入 **设置 → 模型配置**：

- 如果账号所在团队已提供官方**模型池**，它由服务端维护，通常无需填写 API Key。选择其中可用的模型即可；普通/VIP 路由和上游故障转移由后台处理。
- 如果团队允许自行配置，或你在个人工作区使用自己的渠道，点击添加配置，填写供应商类型、名称、Base URL、API Key，并启用需要的模型。

保存后，在 Chat 或 Agent 输入框的模型选择器中选择模型。模型能否用于 Agent，取决于协议、渠道配置和当前内核：

- **Claude 内核**使用 Claude Agent SDK，适合 Anthropic 协议兼容的 Agent 渠道；
- **Pi 内核**使用 Pi Agent SDK，可接入更多已注册的模型渠道；
- Chat 与 Agent 的模型过滤规则不同；
- 思考档位、上下文窗口、工具调用与图片能力也由具体模型决定。

遇到模型列表为空、`model not found` 或 Agent 无法启动时，依次检查：当前模式、模型 ID、渠道开关、协议/Base URL、内核兼容性以及连接测试结果。

> API Key、访问令牌和密码不应写入工作区文件、Skill、定时任务描述或普通聊天内容。

## 三、如何使用 Chat

### 适合 Chat 的工作

Chat 适合：

- 解释概念、比较方案、翻译、润色和总结；
- 根据粘贴内容生成提纲、邮件、文案或表格；
- 讨论代码或设计，但不要求直接修改本地项目；
- 使用联网搜索获取最新公开信息；
- 使用已启用的 Chat 工具生成或编辑图片。

如果你希望模型直接修改文件、运行命令、浏览网页或持续检查一个项目，切换到 Agent 更合适。

### 附件、引用和工具

可以拖入文件，或通过输入框的附件入口选择文件。引用内容时说明文件用途、处理范围和交付格式。面对大文件，优先告诉模型要查的关键词、章节或表格，不要无目标地把全部内容塞进上下文。

输入框提供的引用入口可用于选择文件、会话、Skill 或 MCP。某个入口没有出现时，先检查当前会话是否已绑定工作区，对应能力是否启用。

Chat 工具在 **设置 → Chat 工具** 管理。工具可用性同时取决于当前构建、渠道和配置；启用后一般会显示在 Chat 输入区的工具选择器或对应菜单中。

## 四、如何使用 Agent

### 创建工作区和会话

Agent 的文件和能力围绕工作区组织。一个工作区拥有自己的文件、会话、Skills、MCP 与预设配置。

在 Agent 模式下：

1. 从顶部或侧栏选择工作区；
2. 新建会话；
3. 确认模型、内核、权限模式和预设；
4. 发送目标明确的任务。

没有选中有效工作区时，文件附件、路径引用和部分能力管理入口可能不可用。

### 选择 Agent 内核

输入工具栏中的内核选择器可以在 **Claude** 与 **Pi** 之间切换：

- **Claude**：使用 Claude Agent SDK；
- **Pi**：使用 Pi Agent SDK，拥有独立的会话执行链路并支持其可用的模型渠道。

内核切换在当前会话的下一轮消息起生效。Agent 正在执行或后台等待时不能切换；先等待完成或停止运行。切换后，两个内核不会混用 SDK 会话状态，必要时应在新内核下重新说明关键上下文。

### 使用预设和权限模式

**预设**是“岗位 + 工作环境”：它把提示词、推理强度、权限模式、Skills/MCP 范围与产品工具边界组合成可复用配置。通过输入工具栏的公文包图标切换当前会话预设，下一轮消息会完整生效。

内置预设包括：

- **标准**：完整默认能力；
- **代码**：强调最小改动、验证和代码任务闭环；
- **极简**：收敛任务图、记忆、协作等重型能力，适合短任务。

权限按钮可在三种模式间循环切换：

- **自动审批**：由 SDK 审批器判断，危险操作仍可能请求确认；
- **完全自动**：适合边界明确、低风险且你愿意授权的任务；
- **计划**：先调研、整理方案，获得批准后再执行写入或其他操作。

不熟悉任务时，建议先使用自动审批或计划模式。涉及删除、发布、发送消息、线上数据修改或外部付费时，始终检查工具请求的目标、路径和参数。

### 提示词怎么写

可靠的 Agent 请求通常包含四部分：

- **目标**：最终要得到什么；
- **输入**：使用哪些文件、目录、链接或背景；
- **约束**：格式、范围、不能做的事和风险边界；
- **验收**：完成后检查什么、保存在哪里、如何汇报。

例如：

> 请读取工作区中的 `sales.xlsx` 和 `template.md`。先分析表格中各产品的销售额和成本，再把毛利率写入新的 `sales-report.md`。不要修改原始 Excel。如果数据缺失，列出缺失字段，不要自行猜测。完成后检查报告中的计算公式和文件路径。

不要只说“帮我处理一下这个项目”。任务越可能造成副作用，就越要明确哪些动作必须先停下来确认。

### 过程控制与验收

复杂任务可能展示计划、任务节点、后台任务或协作子会话。不要只看最后一句总结，应查看关键工具调用和写入结果。Agent 被中断、权限被拒或某一步失败时，可以直接说明失败原因和期望的下一步，让它继续；也可以停止后重组任务。

工具栏还可能提供以下控制：

- **思考强度**：高档位通常更适合复杂问题，但会增加时间和消耗；
- **压缩上下文**：适合长会话继续工作，压缩前先将关键决策写入文件；
- **回退**：回到历史消息节点。Claude 与 Pi 对文件恢复的支持不同，回退前请阅读确认提示；
- **消息队列**：在 Agent 工作时暂存下一条消息，自动发送开关按会话保存。

一项任务真正完成的标准不是“Agent 说完成了”，而是：目标文件或结果存在、关键内容已检查、验证失败时已如实记录原因。

## 五、文件、工作区和上下文

### 三类文件来源

右侧文件面板通常会区分：

**会话文件**：只服务于当前 Agent 会话的附件和临时产物，适合一次性输入、草稿和中间结果。

**工作区文件**：当前工作区长期使用的共享上下文，适合项目代码、规范、模板、长期报告和可复用资料。

**附加文件或文件夹**：文件仍保留在电脑原位置，Profer 将其作为当前工作区或会话可访问的目录。适合大型项目、Obsidian 笔记库、素材目录和已有代码仓库。

附加目录不会自动复制全部内容。授权前先确认目录范围，避免把无关的私人文件暴露给会话。

### 文件引用、预览和改动

使用 `@` 选择文件或目录时，引用路径会随消息发送给 Agent。发送前检查引用标签，尤其是存在同名文件或多个附加目录时。

Agent 修改文件后，可在右侧预览查看内容，并在改动面板检查差异。一个实用的习惯是要求 Agent 在收尾时列出：修改了哪些文件、刻意没有修改哪些文件、采用了什么验证方式。

### `.context` 工作台

Agent 会在工作区或会话目录的 `.context/` 下保存过程文件，常见内容包括：

- `todo.md`：当前任务进度；
- `plan/`：执行计划；
- `note.md`：调研和分析结论；
- `handoff.md`：跨会话交接信息；
- `automation/`：自动任务的跨运行记录。

这些文件不是垃圾文件。长期项目应保留整理过的结论，修订过时内容；一次性任务的临时计划可在结束后清理。

### 管理上下文长度

长会话会增加成本和干扰。建议：

- 一个会话围绕一个目标；
- 阶段完成后把决策和结果写入工作区文件；
- 新阶段新建会话，并只引用必要的旧会话或文件；
- 大文件先搜索定位，再读取相关片段；
- 不要让 Agent 每轮重复读取不变的大段背景。

## 六、Agent 技能、MCP 和记忆

### Agent 技能入口

左侧栏的 **Agent 技能** 是工作区能力管理中心。先选择工作区，再通过顶部标签切换：

- **Skills**：工作流手册和可复用操作规范；
- **团队市场**：仅团队工作区可见，用于共享与安装团队 Skill；
- **MCP**：外部服务连接配置；
- **记忆**：工作区长期记忆的查看、搜索和维护；
- **预设**：岗位与能力组合配置。

Skills、MCP、记忆和预设都是工作区范围的能力。切换工作区后，列表和启用状态也会变化。

### Skills：把重复工作沉淀成手册

Skill 通常由 `SKILL.md` 及其辅助资源构成，说明一类任务的步骤、判断标准、输出格式与注意事项。它不是模型，也不是另一个机器人；它是 Agent 在匹配任务时加载的工作手册。

建议只保留真正需要的 Skills。可以直接让 Agent 使用内置的 `find-skills` 查找候选，也可以从其他工作区导入。导入或安装后，在当前工作区确认它已启用，再实际执行一次任务验证效果。

当一个流程已经重复验证成功时，可以让 Agent 使用 `skill-creator` 整理为 Skill。先沉淀真实流程，再根据失败案例补验收标准，通常比一开始写很长的“万能 Skill”可靠得多。

团队工作区可将适合多人复用的 Skill 发布到团队市场。发布前检查并删除个人路径、密钥、内部网址和只适用单台设备的假设。

### MCP：连接外部服务

MCP 是 Agent 连接外部服务的协议。Profer 当前可在能力中心配置命令行 `stdio`、HTTP 或 SSE 等类型的 MCP 服务器。它们可能具有读取文档、访问项目管理系统、操作云服务等权限。

启用 MCP 前请检查：

1. 服务器来源是否可信；
2. 命令、URL 与环境变量是否正确；
3. 它能读取或修改哪些数据；
4. 当前工作区是否真的需要它。

服务器未加载、工具列表为空或调用时报连接错误时，先在 **Agent 技能 → MCP** 中确认启用状态和配置，再检查外部服务本身。

### 记忆：让长期信息可审计、可维护

工作区记忆不是聊天流水账。它用于保存跨会话仍有价值的项目规则、稳定偏好、已验证经验和重要问题状态。能力中心的 **记忆** 标签可以查看、搜索和维护这些内容，也可创建一个初始化会话，让 Agent 在你授权的历史范围内整理高信号信息。

建议将信息分层：

- 项目硬规则、关键入口和常用命令：写入 `CLAUDE.md`；
- 可复用经验、偏好和纠错：写入长期记忆；
- 当前任务的临时计划、调研与交接：写入 `.context/`；
- 一次性讨论、未经验证推断：不要急于写入长期记忆。

写入记忆前，优先让 Agent 说明准备更新什么、为什么更新；对可能变化的状态写明日期。这样下次会话既能复用结论，也能追溯其来源和时效。

## 七、规划中心和定时任务

### Todo 与日程

左侧栏进入 **规划中心**，可在 **Todo / 日程 / 定时任务** 三个标签间切换：

- **Todo**：记录待办、截止日期、分组和状态；
- **日程**：查看和维护日历事件，也会呈现已安排的待办与启用中的自动任务；
- **定时任务**：查看、编辑、暂停、立即运行或删除自动化任务。

Todo 适合需要你判断和推进的事项，日程适合有明确时间安排的会议或事件。它们与 Agent 任务并不冲突：可以先用 Todo 管理目标，再从相关会话让 Agent 协助完成。

### 什么值得自动化

定时任务适合**长期反复、可无人值守、完成后有稳定价值**的流程，例如：

- 每天检查项目或服务器健康状态；
- 每周汇总用户反馈、变更或数据；
- 定期追踪公开资料，在工作区写入增量报告；
- 对固定目录执行一致的整理、审计或复盘。

不适合自动化的场景包括：单次任务、纯闹钟、必须由你实时判断的决策，以及结果没有长期价值的重复动作。它们更适合 Todo、日程或普通 Agent 会话。

### 创建、试运行和维护

推荐直接在 Agent 会话中说明自动化目标、频率、工作区、模型和通知要求，例如：

> 每周一 09:00 检查工作区中上周的 Git 提交和未关闭 issue，输出一份中文周报到 `.context/weekly-report.md`。没有足够证据时明确写出缺口。先创建定时任务并立即试运行一次。

Agent 会判断是否适合创建定时任务，并协助补齐配置。也可以在 **规划中心 → 定时任务** 手动新建。一个可运行的任务至少要有任务描述、模型和工作区；保存后建议先“立即运行”一次，检查生成的会话、写入位置和运行记录是否符合预期。

定时任务可按固定间隔、每天、每周或每月运行，也可配置运行次数上限、会话复用方式、权限模式、预设与飞书通知。任务描述只写要完成的业务目标，不要放 API Key、密码或其他敏感信息。

## 八、受管浏览器、协作与远程连接

### 受管浏览器

Agent 需要访问动态网页、站内搜索、公开表单或页面控件时，可以使用右侧的**受管浏览器**。网页在 Profer 管理的受控环境中运行，Agent 可观察页面、填写公开字段和执行必要交互。

受管浏览器有明确安全边界：不允许访问本机或私网地址、不允许下载文件到任意本地路径、不允许弹窗和网页权限，并会在首次使用前要求阅读风险说明。网页内容也可能是不可信输入；涉及登录、发送消息、发布内容或其他外部副作用时，先检查页面、账号和待提交内容。

静态公开资料检索通常可先使用联网搜索；只有确实需要网页内操作时才打开浏览器。对本地 HTML 或项目页面的预览，使用 Agent 的预览能力，而不是把本地路径当成公网网址访问。

### 协作子 Agent

复杂、可并行且需要保留进展的任务，Agent 可以创建真实的协作子会话，让不同方向独立推进后再汇总。例如：同时审查前端、后端和测试影响，或分别调研多个独立方案。

协作不是越多越好。单文件修改、简单检索或短回答通常由一个 Agent 直接完成更快。使用协作时，重点检查每个子会话的实际发现、证据与未解决风险，而不是只看父会话的一句摘要。

### 远程连接

在 **设置 → 远程连接** 中可配置飞书、微信或钉钉等平台。不同平台的授权和能力不同；配置完成后，可在远程端向 Profer Agent 发送任务或接收结果。

远程执行前，先为对应 Bot 配置工作区、模型和权限边界。飞书还可按界面引导补充 CLI 能力，让 Agent 在授权范围内处理文档、日历、表格或邮件。不要把远程机器人当成无边界的自动执行器：涉及删除、发布、账号操作和敏感文件时仍应保留确认与审查。

## 九、团队协作、安全与故障排查

### 团队工作区

团队工作区适合共享文件、Skills、记忆和协作项目。管理员可在团队管理中维护成员、角色与邀请；成员切换到团队工作区后，应确认当前操作的是共享文件而不是个人目录。

共享前请检查：

- 文件是否包含 API Key、密码、隐私资料或不应外发的客户数据；
- Skill 和 MCP 是否包含本机绝对路径或只适用个人环境的配置；
- 自动任务是否会在不合适的工作区、模型或权限模式下运行；
- 团队成员是否确实需要访问这些内容。

### 设备、账号与数据安全

在 **设置 → 登录设备** 可查看账号已登录的设备，并移除可疑或不用的设备。API Key、登录令牌和机器人凭据应仅通过设置页或受信任的授权流程配置，不要复制进 Markdown、截图或对话记录。

导出备份前确认存储位置；备份可能包含渠道配置与敏感凭据。安装不熟悉的 MCP、Skill 或第三方脚本前，先阅读来源、权限与实际执行命令。

### 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 模型不在选择器中 | 当前是 Chat 还是 Agent、渠道是否启用、模型 ID/协议和内核兼容性 |
| Agent 无法读取文件 | 是否选择了工作区、文件是否已引用、附加目录是否已授权、路径是否正确 |
| MCP 没有工具或连接失败 | MCP 标签中的启用状态、命令/URL/环境变量、外部服务可用性 |
| 定时任务不能启用或运行 | 是否填写了任务描述、工作区和模型；先立即试运行并查看记录 |
| 长会话变慢或答非所问 | 把阶段结论写入文件，压缩上下文或新建会话，只引用必要资料 |
| Agent 修改后结果不符合预期 | 查看改动和工具调用，明确验收条件后让它修正；高风险操作先恢复或停止 |

## 十、推荐的使用方式

1. **从小任务开始**：先让 Agent 创建一个文件、整理一份资料或检查一段代码，确认模型和环境可用。
2. **把要求写成可验收的任务**：说明目标、输入、约束和验收方式，而不只说“帮我处理”。
3. **按目标拆会话**：任务阶段完成后沉淀结论，再新建会话继续下一阶段。
4. **让文件承载上下文**：长期模板、规范和报告放工作区；临时过程放 `.context/`。
5. **只沉淀已验证的流程**：重复成功的工作流做成 Skill，有长期价值的周期流程做成定时任务。
6. **把安全边界说清楚**：删除、发布、发送、付费、线上修改和敏感数据操作，始终先审查再执行。

如果不确定应该用 Chat、Agent、Skill、MCP、预设、Todo 还是定时任务，直接在 Agent 中描述你要达成的结果和限制，让它先给出推荐路径与原因。
