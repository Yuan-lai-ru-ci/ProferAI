# Profer 接入 8-Pay：申请、配置与验收教程

> 目标：为 Profer 的「充值积分」开通微信支付和支付宝。当前代码已兼容易支付协议；本教程只指导申请与准备，**不要求你把商户密钥发送给任何人或贴进聊天**。
>
> 适用前提：你已在 8-Pay（或其他兼容易支付协议的服务商）开始申请。生产上线与 ¥1 验收细则见 [`epay-production-acceptance.md`](./epay-production-acceptance.md)。

---

## 一、先理解要申请的东西

你申请的不是“给 Profer 用户一种新支付方式”，而是让用户仍用熟悉的微信/支付宝付款，而 Profer 服务端通过易支付网关创建订单、接收回调后自动发积分。

```text
Profer 客户端
  → 用户选择微信 / 支付宝和充值金额
  → Profer 服务端创建本地充值订单
  → 8-Pay 支付页 / 二维码
  → 用户完成微信或支付宝付款
  → 8-Pay 回调 Profer 服务端
  → Profer 验签、核对金额、积分到账
```

申请完成后，服务商通常会给你三项关键值：

| 商户后台信息 | Profer 生产变量 | 用途 | 能否公开 |
|---|---|---|---|
| 商户 ID / PID | `EPAY_PID` | 标识你的商户账户 | 不建议公开 |
| 商户密钥 / KEY | `EPAY_KEY` | 下单签名、回调验签 | **绝不能公开** |
| API 网关地址 | `EPAY_API` | 服务端下单地址的根地址 | 可在内部文档记录 |

另有一项由你自己确定：

| 信息 | Profer 生产变量 | 示例 |
|---|---|---|
| 可从公网访问的 Profer 服务端根地址 | `PAY_NOTIFY_BASE` | `https://你的服务域名` |

代码会自动在网关地址后加 `/submit.php`，并自动生成：

```text
异步回调：https://你的服务域名/v1/payment/notify
支付完成返回页：https://你的服务域名/v1/payment/return
```

## 二、申请表怎么填

不同服务商字段略有不同，以下按常见申请项填写。以服务商页面规则为最终准则，遇到不确定的字段先问客服，不要猜填。

### 1. 主体类型

按你的实际主体选择：

- 有公司/个体工商户：优先选**企业或个体工商户**。
- 暂无营业执照：仅在服务商明确允许个人主体、且其条款明确允许软件服务/数字化服务时选择个人。

**建议**：Profer 目标是 B 端团队产品，长期应以企业或个体工商户主体承接支付；个人主体可以只作为早期小额验证路径，不应承诺长期可用性、无限额或所有支付方式都能开通。

### 2. 商品/业务描述

不要写“虚拟币”“代充”“代购”“API 转售”或含糊的“其他”。建议如实、清楚地写成：

> Profer 是面向团队和个人的桌面 AI 工作效率软件，提供 AI 对话、任务协作、自动化与知识整理能力。用户购买软件内的预付费使用积分，用于支付平台托管的 AI 服务调用；不提供现金提现、转账、博彩、证券、虚拟货币或第三方代收付服务。

如需要更短版本：

> AI 工作效率软件的预付费使用积分充值，用于软件内 AI 功能调用，不可提现或转让。

只在内容完全符合实际时使用上述文字；支付渠道审核最看重业务真实性和可解释性。

### 3. 网站/产品地址

填写用户和审核人员实际能访问的地址：

- 官网：`https://profer.cn/`（若当前仍是正式站点）；
- 若申请表要求“交易网站”：填可展示产品介绍、价格或下载入口的正式页面；
- 若要求“回调域名”：填写 Profer 服务端的公开域名，不能填本机地址、IP 内网地址或 `localhost`。

不要把 `47.109.108.57` 的裸 IP 当作用户交易站点填写，优先使用 HTTPS 域名。申请提交前打开无痕窗口检查：页面能访问、产品描述和主体信息不明显冲突、没有测试文案或失效链接。

### 4. 联系与结算信息

- 联系人、手机号、结算银行卡/支付宝账户必须使用实际可验证且与主体相符的信息。
- 结算周期、手续费、最低提现额、是否冻结资金、退款费用应在提交前截图或记录到你的私密经营资料。
- 不要使用他人身份证、他人商户账号或租借通道。这不仅容易触发风控，也会造成资金和合规风险。

## 三、提交前准备清单

### 你需要准备

- [ ] 主体材料：营业执照/个人身份材料，以页面要求为准；
- [ ] 结算账户信息；
- [ ] 可接收验证码的手机号和邮箱；
- [ ] Profer 官网或可公开访问的产品介绍页；
- [ ] 软件截图：订阅设置中的「充值积分」、微信/支付宝选择界面；
- [ ] 清晰的业务说明（可使用上节模板后按真实情况修改）；
- [ ] 客服支持或退款联系渠道；
- [ ] 服务端公开 HTTPS 域名的计划。

### 提交前向客服确认

把下面问题逐项问清楚，答案不清晰不要急着充值开户费：

1. 是否支持软件服务、数字化工具、AI 工作效率工具的预付费积分业务？
2. 是否同时可开通 `wxpay` 与 `alipay`？各自的主体、资质、限额要求是什么？
3. 是否完全兼容易支付接口：`submit.php`、`notify_url`、`out_trade_no`、`money`、`trade_status=TRADE_SUCCESS`、MD5 签名？
4. API 网关地址是根地址还是已包含 `submit.php`？
5. 回调采用 POST 吗？成功时接受纯文本 `success` 吗？是否有 IP 白名单要求？
6. 首笔/单笔/单日交易限额、D+几结算、手续费、最低提现额、冻结期、退款手续费分别是多少？
7. 商户密钥能否在后台自行重置？重置后旧密钥是否立即失效？
8. 发生投诉、退款、风控冻结时，谁负责处理、时限和所需材料是什么？

## 四、审核通过后，先做“配置交接”，不要马上启用

审核通过后，在商户后台找到并保存：

```text
API 网关地址：________________
商户 PID：_____________________
商户 KEY：_____________________
已开通支付方式：□ 微信  □ 支付宝
费率：________________________
结算周期：____________________
单笔/单日限额：_______________
客服工单或支持渠道：__________
```

保存位置应是你的密码管理器或生产服务器受限配置文件，**不是 Git、普通 Markdown、截图相册、聊天记录或 Issue**。

此阶段你只需要告诉我下列非敏感信息，我可以继续核对兼容性：

```text
- 网关地址是否以 /submit.php 结尾（不要发 KEY）
- 支持的支付 type 名称（是否 wxpay / alipay）
- 回调字段和成功状态名
- 是否要求回调 IP 白名单
- 是否已拿到可用的 PAY_NOTIFY_BASE 域名
```

`EPAY_KEY` 不要发送。若需要我协助写入服务器配置，应使用 Profer 的受控部署流程或由你自行写入 `.env`，我只检查变量是否“已设置”，不输出它的值。

## 五、上线前的正确顺序

```text
申请审核通过
  → 确认接口兼容性、费率、限额与业务类目
  → 配好服务端 HTTPS 域名和回调路径
  → 将 PID/KEY 安全写入生产 .env
  → 运行部署 dry-run
  → 部署服务端
  → 开启 PAY_ON_RECHARGE=1
  → 用测试账号完成 ¥1 真支付
  → 核对订单、余额、账本和重复回调
  → 再向真实用户开放
```

不要反过来：**未完成 ¥1 验收前，不要在官网、更新说明或聊天中宣布已支持在线充值。**

### 配置放置位置

生产服务器仅在下面文件配置真实值：

```text
~/proma-team-server/.env
```

示例（全部用你自己的真实值替换占位符）：

```dotenv
PAY_ON_RECHARGE=1
PAY_NOTIFY_BASE=https://<Profer服务端公开域名>
EPAY_API=https://<支付网关根地址>
EPAY_PID=<商户PID>
EPAY_KEY=<商户KEY>
```

然后按 [`epay-production-acceptance.md`](./epay-production-acceptance.md) 的部署和 ¥1 验收章节继续。不要把这五项写进仓库 `server/.env.example`。

## 六、常见问题

### 服务商问“你卖的是什么”

如实说明是软件内的预付费使用积分，用户获得的是 AI 功能使用权，**不可提现、不可转让、不可兑换现金**。不要把积分包装成投资、理财或虚拟资产。

### 服务商只支持微信或只支持支付宝

可以先接入一个通道进行内部 ¥1 验收，但对外开放前建议补齐另一个。前端已经支持 `wxpay` 与 `alipay`；若渠道实际只开通一个，需要在上线前把未开通方式隐藏或禁用，不能让用户点到一个必然失败的支付方式。

### 服务商要求回调 IP 白名单

你需要拿到 Profer 服务器的**对外出口 IP**，不是容器内部地址。服务器位于云主机/NAT/反向代理后时，以实际出口 IP 为准；配置前先向服务商确认是限制“支付网关 → Profer 回调”的来源 IP，还是限制“Profer → 支付网关下单”的出口 IP。

### 我只想先人工收款

保持 `PAY_ON_RECHARGE=0` 或不配置完整支付变量。客户端会自动退化为创建人工订单并复制管理员微信号，管理员确认收款后积分到账。

### 要退款怎么办

当前版本已具备充值和到账，不应在没有退款业务规则、权限和账务闭环前承诺自动原路退款。收到退款请求先按服务商协议和实际到账情况人工处理，并记录关联订单 ID；自动退款应另立需求实施。
