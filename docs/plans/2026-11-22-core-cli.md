# Profer CLI 与独立 Core 实施计划

**目标：** 终端、桌面和已配对客户端使用同一个独立 Core，共享会话、历史、模型配置与配对。完全退出 Profer 停止本机 Core；重启不丢已保存的数据。

**参照 Claude Code：** 在项目目录调用；`-p`/`--print` 脚本入口；`--continue` 最近会话、`--resume` 同一会话；交互使用同一后端。不复制 Claude 的内部部署方式。

## CLI 模型配置

配置入口放在 CLI，存储和运行由所属 Core 负责；不从 Electron 复制密钥，不改旧桌面配置。以下命令需要可独立运行的本机 Core（当前入口限 macOS / Linux）。

```bash
profer channel add --name Anthropic --provider anthropic --model MODEL_ID
profer channel list
profer channel rotate-key CHANNEL_ID
profer -p "你好" --workspace default --channel CHANNEL_ID --model MODEL_ID --runtime pi
```

添加或轮换时在终端隐藏输入；脚本可通过 stdin 提供一行 Key，不接受 `--api-key` 参数。`--resume` 和 `--continue` 沿用旧会话的渠道、模型与 Runtime，不因新会话选项改绑。`--workspace default` 使用独立本机 Core 建立的默认工作区。

验收：编译版 CLI 在空数据根创建并轮换渠道；PTY 不回显 Key；Core 重启后，真实 Pi adapter 对回环模型服务发请求，验明使用的是轮换后的 Key 和指定模型；Claude adapter 另用现有 SDK 替身验证从 Core 存储加载同类凭据。不访问真实模型供应商。

- 桌面同源验收：`test/core-cli-desktop-channel.integration.test.ts` 使用隔离 Core、真实 CLI 和桌面主进程的发送预检/CoreClient；CLI 首轮后轮换 Key 并停止、重启同根 Core，桌面发送续用原会话且不传凭据，回环模型只接受新 Key，历史最终有两条用户消息。相关回归 22 通过；Electron 类型检查和 main 构建通过。新版隔离 Mac Electron 经 `--quit` 后，原 Core 退出 0、释放写锁；重启保留身份和 CLI 渠道。未驱动原生聊天界面。
- 真实供应商验收：最初指定的模型 ID 返回 `404 model_not_found`；用户确认改用目录中的 `deepseek-v4.1-flash` 后，两轮受限请求均返回 HTTP 200（CLI 首轮、Core 停止并重启后经桌面主进程发送契约续接）。13 条断言验证同一 Core ID、同一会话、两次不同 run 和共享历史，桌面请求没有携带模型 Key。独立验收脚本限制每个阶段最多发一次请求、每次最多 64 输出 token，不请求标题、不自动重试。未验证 Windows 原生界面或替换默认配置。

- 三机联合验收（Mac / Windows / Ubuntu）：Mac 编译版 CLI 开首轮，Windows 原生 Node 调用产品 Core 客户端续接、Ubuntu 观察；Mac Core 停止并重启后，Ubuntu 用原授权续接、Windows 观察。真实 TLS 固定身份 + WSS；两台远端各一份邀请；同 Core ID、同 session ID、三个 run、三条用户消息，三轮 `deepseek-v4.1-flash` 请求 HTTP 200。原配对可用指客户端库重连，不等同于 GUI 的自动恢复或系统凭据保存实测。
- 三机用户入口：独立 Core 空会话可直达模型配置，配好并刷新后可选模型；设置标明新版 CLI、随包路径和数据根。Mac 隔离验收包中随包 CLI 冷启动及配置、桌面启动复用原 Core、完整退出停服、CLI 重启保留目录均通过。配对入口是「设置 → 远程连接 → 内核连接」，导入完成后仍需用左栏「当前内核」切换。旧安装与 PATH 不自动切换；未跑 Windows/Ubuntu 原生界面点发和重启恢复。

## 本轮证据与接续

- CLI：`bun test --isolate apps/cli` 32 通过；编译版 PTY 验收 `core-cli-tty-verify.py` 验证从无桌面冷启动、看到流式预览、两轮对话、退出后续接同会话。渠道预先由 Core 持久化，并非凭据迁移验收。
- 早期 macOS 三端隔离验收：在「退出桌面只断开连接」的旧实现下，CLI 和配对 WSS 端各完成一轮并读到同一历史。这证明客户端断连不影响 Core，不替代现行「退出 Profer 停止本机 Core」的联合验收。
- Claude / Pi：现有 Core adapter 测试分别 2、12 项通过；三端夹具仍用通用 mock。
- 第 2 轮：`--resume` / `--continue` 无新提示词时先订阅再查权威快照。编译版 PTY + 真实 Pi SDK/adapter、脚本模型传输确认原 `runId` 完成且只落一条外部用户消息（12 条断言）。协议测试将另一客户端处理请求、查快照时完成、以及断线纳入回归。
- 第 3 轮：确认产品语义为「完全退出 Profer = 停止本机 Core」。新增 `profer core stop`，owner-only 回环管理请求在 202 响应后完成优雅关机、撤下描述符并释放写锁；配对设备不能调用。Electron 的正常退出对独立 Core 使用同一协议，内置 Core 仍由桌面子进程正常停止。
- 第 3 轮验证：CLI / Core / Electron 相关 typecheck；CLI 32 项、Core shutdown/connection 及 Electron lifecycle 回归均通过；Electron build:main 通过。
