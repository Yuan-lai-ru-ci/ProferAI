# Profer 上手

> **5 分钟，从「能聊天」到「能把事做完」。** 第一次使用只看前半部分；遇到具体问题，直接翻后面的章节。

本教程按当前桌面端（v0.16.x）源码整理。客户端教程真源是 `apps/electron/resources/tutorial.md`，`tutorial/tutorial-v2.md` 是同步稿；教程正文也会作为首次欢迎对话的参考附件。入口会受 Chat/Agent 模式、登录状态、工作区、开发者模式、预设和账号能力影响，看不到某个入口时，先看第 14 节的排错。

## 先选一条路

| 你想做的事 | 去哪 | 怎么开始 |
| --- | --- | --- |
| 问问题、翻译、润色、想方案 | **Chat** | 打开就能问，不需要工作区 |
| 读文件、跑命令、改代码、做多步任务 | **Agent** | 选一个工作区，说清目标和验收 |
| 每天 / 每周重复的事 | **规划中心（定时任务）** | 建一个定时任务，到点自动跑 |

拿不准就用 Chat 问一句；需要动文件、执行命令时再切到 Agent。左侧栏顶部可以随时切换，⌘B 收起侧栏。

## 第一次使用，先做这三件事

1. **确认有可用模型**：打开 **设置 → 模型与能力 → 模型配置**，至少启用一个当前模式能用的模型。
2. **切到 Agent，选一个工作区**：新建会话，确认输入区上方的模型、运行时内核（Claude / Pi）、权限模式和预设。
3. **发一个能验收的任务**：别问「你能做什么」，直接给目标、输入、约束和验收标准。

可以直接复制这一段：

```text
在当前工作区创建 hello.md，写入项目名称、目标和技术栈。
完成后告诉我文件路径，并重新读取文件确认内容存在。
```

跑完检查文件路径和内容，就算走完第一轮。任务写得越具体，Agent 越少来回确认：

- **目标**：最后要得到什么；
- **输入**：用哪些文件、目录、链接或背景；
- **约束**：不能改什么、格式是什么、哪些动作要先确认；
- **验收**：完成后检查什么、结果保存在哪里。

## 十个可以直接复制的任务

| 想做的事 | 直接这样说 |
| --- | --- |
| 读文档 | `读取 @季度报告.pdf，用 5 条要点总结，每条附原文页码。` |
| 改文件 | `把 @周报.md 改写成给管理层看的版本，不超过 400 字，保留所有数字。` |
| 分析表格 | `分析 @销售.xlsx 的下滑原因，输出结论、证据和下一步建议。` |
| 写代码 | `给登录接口补一个失败重试，改完运行测试并贴出结果。` |
| 查资料 | `查一下这三家竞品最近的定价变化，给出对比表和来源链接。` |
| 做 PPT | `把 @方案.md 做成 8 页 PPT，深色、克制，图表用真实数据。` |
| 建 Skill | `把刚才这套周报流程存成 Skill，名字叫「周报生成器」。` |
| 定时任务 | `每周一 9 点整理上周的项目进展，写成摘要并提醒我。` |
| 整理日程 | `把这段话里的安排拆成 Todo 和日程，时间冲突要指出来。` |
| 复盘 | `回顾这个会话：做过什么、改过哪些文件、哪些还没验证。` |

附件可以直接**拖进输入框**：会话文件、工作区文件和变更列表都支持拖拽，会自动生成 `@` 引用；发送前确认引用的是哪个文件。

## 卡住了？先看这三处

- **输入框没有模型**：去 **设置 → 模型与能力 → 模型配置** 启用一个模型；订阅渠道要确认它支持当前模式。
- **Agent 不动或报权限**：先看权限模式和工具请求；Windows 还需要可用的 Git Bash 或 WSL。
- **找不到入口**：确认当前是 Agent 模式、已选工作区、需要登录的页面已登录。完整清单见第 14 节。

## 1. 找到真实入口

### 教程入口

教程入口是 **设置 → 帮助 → Profer 教程**。点击后，设置面板关闭，教程会在主区打开一个独立的“Profer 使用教程”标签页，不会覆盖已有会话。

教程也可能由首次引导或教程推荐横幅打开。横幅点击“立即学习”和“稍后再学”都会关闭横幅；之后仍可从设置重新打开教程。

### 主界面入口

左侧栏中的入口会随模式和状态变化：

- **模式切换**：Chat 和 Agent 两种会话模式；
- **Agent 工作区**：Agent 文件、会话和工作区能力的边界；
- **规划中心**：Todo、日程、定时任务、Goal 四个分区，已拆成 rail 上独立的入口（带计数）；
- **Agent 技能**：Skills、MCP 和预设；仅 Agent 模式显示；
- **Agent 记忆**：当前工作区的长期记忆；仅 Agent 模式显示；
- **我的画像**：跨工作区的用户画像与全局记忆（设备清单、服务器目录、长期记忆文件、活跃热力图）；
- 设置、账户和连接入口。

主区标签可能包括 Chat、Agent、文件预览、受管浏览器、插件页面和教程。会话标签支持**拖拽排序**；顶栏标签上右键可以「关闭其他 / 关闭右侧」。文件预览与受管浏览器都是工作标签，不要把浏览器理解为始终固定在右侧的面板。会话可以拖出或右键「移到新窗口」，生成只渲染该会话的独立窗口，也可以移回主窗口。

### 为什么入口可能不存在

先检查四件事：

1. 当前是否处于 Agent 模式。
2. 是否已选择工作区。
3. 是否已登录团队账号；额度、订阅和部分服务端渠道需要登录。
4. 是否开启开发者模式；开发者与插件入口默认隐藏。

当前版本**不再提供团队工作区**：桌面端团队工作区运行时已移除（入口、IPC 与同步链路一并下线）。团队账号登录、额度与订阅属于账户能力，仍然保留。

## 2. Chat、Agent 和工作区

### Chat 适合什么

Chat 适合：

- 解释概念、比较方案、翻译、润色和总结；
- 根据粘贴内容生成提纲、邮件、文案或表格；
- 讨论代码或设计，但不要求直接改动本地项目；
- 使用已启用的联网搜索或图片工具。

图片消息支持右键复制到剪贴板。Chat 是否能使用某个工具，取决于当前构建、工具配置、渠道和账号能力。

### Agent 适合什么

Agent 适合：

- 读取、创建和修改工作区文件；
- 执行命令、检查项目状态和运行验证；
- 使用 Skills、MCP、预览和受管浏览器；
- 把一个目标拆成连续步骤，保留进展并汇总结果。

Agent 的文件和能力围绕工作区组织。没有有效工作区时，文件引用、附件和部分能力管理入口可能不可用。

### 工作区两态：managed 与 project

- **managed 工作区**：数据全部存在 Profer 的中央目录；
- **project 工作区**：以你已有的项目目录作为工作区，用项目内的 `.profer/` 作为配置根；会话 cwd 就是项目根，但会话数据、检查点与附件仍留在中央工作区，**绝不写进项目仓库**（`git status` 保持干净）。同一目录只允许一个工作区；项目移动后可重新绑定目录；删除工作区只删索引，不碰项目文件。

工作区可以**附加到已有目录**：文件仍保留在电脑原位置，Profer 获得访问范围，适合大型项目、Obsidian 笔记库和已有仓库。授权前确认目录范围，避免把私人文件暴露给 Agent。

### 如何写一个可靠任务

请求至少包含四部分：

- **目标**：最后要得到什么；
- **输入**：使用哪些文件、目录、链接或背景；
- **约束**：不能修改什么、格式是什么、哪些动作要先确认；
- **验收**：完成后检查什么、结果保存在哪里。

示例：

> 请读取工作区中的 `sales.xlsx` 和 `template.md`，分析各产品销售额与成本，把毛利率写入新的 `sales-report.md`。不要修改原始 Excel；数据缺失时列出缺口，不要猜测。完成后检查公式、文件路径和报告是否存在。

涉及删除、发布、发送消息、线上修改、账号操作或付费时，要在请求中明确确认边界，并检查 Agent 的工具请求。

### 运行中还能继续发消息

Agent 运行时追加的消息进**队列**：可编辑、删除、拖拽排序，轮结束后自动发送队首；「停止」会暂停自动发送但保留队列，下一次显式发送或空闲时恢复。运行中发送不再排队等待空闲——直接插入当前轮。

## 3. 会话过程：文件改动、回退与交接

### 文件改动 chip

Claude 的 Write/Edit 与 Pi 的受控写入、Bash 实际落盘改动，都会以「文件改动 chip」挂在消息气泡上；历史回放同样可见。Bash 产生的改动归属为「未确认」，不猜路径。点 chip 可以打开对应文件的预览。

### 会话回退（Shadow Git）

在回复操作栏点「回退到此处」，可以回退对话，并选择**同时恢复文件**：按轮次记录受控写入（Write/Edit 与 Pi 受控回调）的 before/after 证据，支持「预览 → 执行 → 撤销」全链路；Bash 改动只报告、不猜路径。回退后下一轮会明确告知模型「上一轮已被回退」，不会假装没发生。首次使用回退会在配置目录建立 Shadow Git 影子仓库，不写入项目本身。

### 长会话交接

会话越长，上下文越容易在压缩里丢失细节。达到轮数阈值或上下文占用 80% 时，会在输入框上方提示把当前进展整理成交接文档，并带着它开一个新会话（设置 → Agent 配置 → 长会话，默认关闭）。收到提示时先让 Agent 把结论沉淀到文件，再开新会话继续。

## 4. 首次启动、账户和数据

### 首次引导

首次启动会经过欢迎页和功能导览。Windows 上执行 Agent 命令通常需要可用的 Git Bash 或 WSL，按环境检测页提示处理；其他系统以当前安装包检测结果为准。

首次引导还提供已有数据迁移入口。迁移前先在原设备导出备份，再在目标设备导入。备份可能包含渠道配置和敏感凭据，只保存到可信位置。

### 本地使用和团队账号

Profer 可以先以本地工作区使用，不必因为看不到团队页面而停止本地工作。

团队账号主要影响：

- 团队账号登录与账户资料；
- 额度、订阅和账户服务；
- 服务端官方渠道和模型池；
- 远程服务或其他需要服务端授权的功能。

未登录时，设置导航会隐藏额度、订阅和账户管理等需要认证的页面。团队账号登录、退出与登录设备管理仍可用；团队工作区已下线。

### 项目会话自包含

项目工作区（project 态）的会话消息、任务图、Harness 与 Pi transcript 落到项目内 `.profer/sessions/<id>/`，大载荷进 `.profer/blobs`。整个项目文件夹拷到另一台电脑后打开即可恢复列表与对话，`index.json` 缺失时也能按 `session.json` 对账重建；备份导出可只选会话，不带配置。注意 `.profer/` 已在默认忽略规则内，不要提交到项目仓库。

### 备份与敏感信息

进入 **设置 → 系统 → 数据管理** 管理备份：个人备份 `.profer-backup` 含敏感凭据，用于可信设备间迁移；团队分发 `.profer-share` 可自选组件并剥离凭据。导入前看清内容和冲突提示，完成后重新检查渠道与文件，不要直接把整个数据目录复制给别人。

渠道 API Key 与订阅 OAuth 凭据由主进程加密保存：优先使用系统 `safeStorage`，不可用时使用设备身份派生的 AES-GCM；两条加密链路都失败时中止保存，不落明文。加密存储不等于备份可以公开分享。

旧加密凭据读取失败时，保留原文件与备份，优先在原设备、原系统用户下恢复；不能恢复时，在设置中替换 Key 或重新授权。不要把坏密文当成 API Key 填回。新 `proferss1:` 格式不保证旧客户端能够读取，降级安装前先导出个人备份并准备重新配置凭据，不承诺任意版本无损降级。

不要把 API Key、访问令牌、密码或机器人凭据写入工作区文件、Skill、定时任务描述、截图或普通聊天内容；MCP 的普通配置文件也不是秘密保险箱，详见第 8 节。

## 5. 模型配置：商业模型池与自配渠道

进入 **设置 → 模型与能力 → 模型配置**。页面显示什么，取决于登录状态、商业模式和账号自配权限。

### 商业模型池

如果账号获得服务端模型池：

- 直接选择页面列出的可用模型；
- 通常不需要在客户端填写上游 API Key；
- 普通/VIP 路由、上游主备和故障重试由后台处理。

展开官方模型池可启用或停用渠道及其模型；这些是本机选择偏好，同步会保留已有启停状态，不会改写上游密钥、协议或账号权限。官方配置不是可自由编辑的自配渠道。可用性条反映最近请求的采样，不是当前请求必定成功的保证。模型列表先显示本地快照，商业模式再后台同步；权限或列表读取失败时按页面的“重试权限”“重试”处理，不需要删除已有渠道。

**注意**：渠道自配已不再按会员等级拦截——渠道新建、修改、删除与登录对账号开放，不再区分商业模式下的权限分级；开源版构建则隐藏账号、额度、订阅和官方生图界面。

### OSS 或自配渠道

如果当前构建和账号允许自行配置：

1. 新增或编辑渠道。
2. 选择供应商类型，确认原生协议和需要启用的 Pi/Claude 模式。
3. 填写名称、端点与 API Key；订阅授权走下文的专用登录入口，Ollama 与本地模型的 Key 可选。
4. 获取或手动添加模型 ID，逐个启用需要的模型，创建并检查保存状态。
5. 回到 Chat 或 Agent 输入区选择模型。

当前配置页列出 24 个 provider 类型，包含 API、Coding Plan、兼容协议、订阅、Ollama 与本地 OpenAI 兼容服务；类型数量不是每个账号能用的模型数量，也不代表所有类型都支持 Chat、Claude 和 Pi。**Agent-only** 订阅渠道是 ChatGPT 订阅（Codex）和 xAI 的 Grok/X 订阅 OAuth：只供 Pi Agent，不会进入 Chat 选择器；xAI API Key 可以用于 Chat，Pi Agent 属实验能力；xAI/Codex 均不支持 Claude。

自定义 OpenAI 兼容格式应填写完整 `/chat/completions` 请求端点；Anthropic 兼容格式按其 Messages 端点配置。Claude 使用独立的 Anthropic 端点，留空的推导方式见字段提示；不要以为勾选 Claude 就能把 OpenAI-only 服务变成 Anthropic 服务。DeepSeek 的 Chat 与 Agent 端点路径可能不同，修改地址后分别核对测试结果和实际模式。

Chat 和模型发现直接请求允许带查询参数的完整端点；当前 Pi/Claude SDK 的 Agent 地址不支持 query/hash 路由，含 `?` 或 `#` 时会明确拒绝，不会静默删除参数。Agent 应使用供应商提供的不带 query/hash 的协议地址。

Ollama 读取的是已安装模型目录，不会自动下载模型；只有地址确实指向本机时才是本地请求，远程地址会离开本机。本地模型渠道统一连接 LM Studio、Unsloth Studio、llama.cpp、vLLM 等服务的 OpenAI 兼容 `/v1` 端点，表单预设只填默认端口；服务需由用户自行启动，Profer 不会拉起服务或下载模型。若本地服务同时提供 Anthropic 兼容入口，可另勾 Claude 内核。Chat 与 Agent 的过滤规则不同，Agent 还会按运行时、协议、渠道启用状态和 `agentRuntimes` 过滤。

**推理档位**：官方模型按模型维度声明推理能力（如 Mistral 等），已开通推理的账号能用上思考档位；同渠道第三方模型 id 的推理档位保持禁用，不要手动启用。

### ChatGPT 订阅（Codex）与 xAI 授权

在允许自配渠道的模型配置页操作：

1. **Codex**：新增渠道选“ChatGPT 订阅 (Codex)”，确认名称、Pi 模式和模型，然后点“登录并创建”或“创建时登录 ChatGPT 订阅”。授权在系统浏览器完成，成功后才创建渠道；已有渠道可点“重新授权 ChatGPT 订阅”。
2. **xAI**：选“xAI / Grok”，再选 API Key 或“Grok/X 订阅 OAuth”。API Key 使用 xAI API 计费；订阅入口使用 SuperGrok 或 X Premium，点“登录并创建 Grok/X 订阅”，按系统浏览器中的设备授权流程完成。已有渠道可重新授权；想在 Agent 使用时检查 Pi 模式及“启用实验性 Agent”。
3. 等待期间可点“取消授权”。取消或授权失败不是创建成功；已有渠道重新授权失败不会被失败结果替换。

OAuth 凭据由专用授权流程在本机加密管理，不需要你复制 access/refresh token 到聊天或文件。xAI 的订阅渠道不能直接改作 Chat Key 使用；切换到 API Key 认证要填新的 Key，切回订阅要先完成授权。

“读取 Codex 目录”“读取 xAI 目录”只读取 Pi 内置 **catalog（模型目录）**，不是网络连通、授权成功、余额或账号可用性测试。目录中出现模型不等于你的订阅拥有该模型。明确指定的 Codex 模型不在当前目录时会要求重新读取目录并选择，不会偷偷换用另一个模型。订阅表单不提供普通 API Key 的“测试连接”；实际能否调用仍需在已授权的 Pi 会话中验证，可能使用订阅额度。

### 保存、重试和离开

新建渠道需要点“创建”或“登录并创建”；编辑已有渠道会防抖自动保存，也有“保存”按钮。观察“保存中…”“有未保存的更改”“已保存”或“未保存”状态，不能把点击动作当成已落盘。失败草稿留在当前表单，用“重试保存”重新提交。

有未保存内容时，返回、切换设置分类或关闭设置会进入保存确认路径。“保存并离开”只有保存成功才离开；“放弃并离开”只放弃未提交内容，不撤销已自动保存的字段。

### 连接测试实际覆盖什么

普通 API Key/Ollama 表单的“测试连接”使用当前草稿，不必先保存：有启用模型时只测试**第一个启用模型**的短生成请求；没有启用模型时仅检查目录可达，并明确提示“未验证模型生成”。按勾选的内核分别显示 Claude 端点与 Pi / Chat 原生协议结果。

生成测试会发出真实供应商请求，可能消耗额度；它不覆盖所有模型、完整 Agent 工具调用、长上下文、图片输入、限流或后续稳定性。批量获取目录也不是批量生成测试。

测试和目录获取都可以中途取消（按钮此时显示“取消测试”/“取消获取”）；单次请求 15 秒超时仍有效，超时后如实报错，不会无限转圈。

### Claude、Pi 与渠道资格

Agent 有两个运行时内核：**Claude** 和 **Pi**。它们不是两个模型名称，而是两条不同的 Agent 执行链路：

- Claude 使用 Claude Agent SDK；
- Pi 使用 Pi Agent SDK；
- 每个会话有自己的运行时元数据；
- 运行中的会话不能切换内核；
- 切换后，Claude 与 Pi 的 SDK 会话、分叉和恢复状态不会混用，必要时重新说明上下文。

会话内核不兼容的渠道在模型选择器中仍会展示但**置灰并说明原因**，不再让你以为模型丢失。能否使用某个渠道，以渠道页面显示的 runtime 资格为准，不要简单按供应商名称推断。

模型列表为空、`model not found` 或 Agent 无法启动时，依次检查：当前模式、认证方式、模型 ID 与模型启用状态、渠道是否启用、协议/端点、runtime 资格和连接结果。预设限制的是工具与行为，不会替你补齐渠道认证或创建缺失模型。

## 6. Agent 内核、预设和权限

### 切换 Claude 或 Pi

在 Agent 输入工具栏选择运行时内核。切换在后续消息生效；Agent 正在运行或后台等待时不能切换，先停止或等待当前运行结束。

不要把 Claude 和 Pi 当作可互换的会话容器。两者的 SDK 会话文件、恢复和部分工具名称不同。Pi 的文件检查点与 Claude 的文件历史机制也不同，回退或分叉前阅读界面提示。

### 预设是什么

预设是可复用的“岗位 + 工作环境”配置，可能包含：

- 系统提示词和岗位说明；
- 思考强度与权限模式；
- **渠道与模型绑定**：预设可以绑定渠道，绑定渠道时必须同时选择模型；创建、更新、复制、提升全局都会透传渠道绑定。协作子会话还可以绑定一个**委派模型**，从该预设创建的子会话固定使用这个模型；调用时显式传 `modelId` 仍可覆盖，未绑定时沿用父会话当前模型；
- Skills、MCP 和内置工具范围；
- 任务图、记忆、协作、定时任务等工具组是否可用。

输入区的公文包入口用于为当前会话选择预设，变更在下一轮消息生效；当前轮能力不会因此扩大。预设管理不在“设置 → Agent 配置”中，而在左侧 **Agent 技能 → 预设**。预设可能属于当前工作区，也可能是全局预设；工作区还可以设置新会话默认预设。

用户预设可以裁剪能力，包括任务图、记忆、协作、自动化与规划、受管浏览器、剪贴板和 PPT 交付等工具组；关闭后，Agent 不能自行恢复或改用旁路工具。排查“工具不见了”时，先检查当前会话绑定的预设及其启用范围，再明确选择合适的预设或调整设置。

可以明确让 Agent 列出预设、创建或复制当前工作区预设、切换本会话预设；创建/复制不会自动切会话或改默认。更新或设为默认先返回影响提案，下一条消息明确确认后才提交；删除、全局作用域和批量改绑在预设管理界面处理。

### 权限模式

权限模式决定 Agent 遇到工具操作时如何处理：

- **自动审批**：按当前审批器和安全规则处理，必要时请求你确认；
- **完全自动**：适合边界清晰、风险可接受且你明确授权的任务；
- **计划**：先调研和整理计划，批准后再执行写入或其他动作。

定时任务、飞书/headless、移动端等无人值守入口在 bypassPermissions 权限下不再卡在「等待批准」，权限端口直接放行且不产生审批请求。权限模式不会替你确认外部事实，也不应被当作删除、发布、发送或付费的自动授权。高风险操作始终检查目标、路径、参数和最终内容。

## 7. 文件、工作区和上下文

### 三类文件

- **会话文件**：当前会话的一次性附件、草稿和中间产物。
- **工作区文件**：项目代码、规范、模板、长期报告和共享上下文。
- **附加文件或目录**：文件仍保留在电脑原位置，Profer 获得当前工作区或会话的访问范围。

### 引用、预览和改动

使用输入框的 `@` 入口引用文件或目录，也可以直接**拖拽文件进输入框**，发送前检查实际路径，尤其注意同名文件和多个附加目录。引用发送后会写成正文里的 `[n]` 标记和引用块，点胶囊能跳回原消息；悬停胶囊 750ms 可预览来源与原文。

Agent 修改文件后：

1. 在文件面板或预览中查看结果；
2. 在改动面板检查差异；
3. 要求 Agent 报告修改文件、未修改文件和验证方式；
4. 对重要结果重新读取或运行相关测试。

### `.context` 工作台

Agent 可能在工作区或会话目录的 `.context/` 中保存任务过程，例如计划、Todo、调研结论和交接信息。它们服务于当前任务或项目上下文，不是产品垃圾文件。

按范围管理：当前任务的临时资料放会话级 `.context/`；跨会话仍有价值的结论放工作区文件或长期记忆；未经验证的猜测不要写入长期资料。

### 上下文长度

一个会话围绕一个目标推进。阶段完成后把决策和结果写入文件，再开始下一阶段。大文件先搜索定位，再读取相关片段；长会话变慢或答非所问时，用第 3 节的交接机制或压缩上下文，然后新建会话，并只引用必要资料。

## 8. Agent 技能：Skills、MCP 和预设

左侧栏进入 **Agent 技能**（全屏视图，顶部标签 Skills / MCP / 预设，仅 Agent 模式显示）。先选择 Agent 工作区，再选择顶部标签：

- **Skills**：工作流手册和可复用规范；
- **MCP**：外部服务连接配置；
- **预设**：工作区和全局预设。

未选择工作区时，可以管理部分全局配置，但不能假设工作区级 Skills 或 MCP 已经生效。切换工作区后，列表和启用状态可能改变。

### Skills

Skill 通常包含 `SKILL.md` 和辅助资源，描述一类任务的步骤、判断标准和输出格式。它不是模型，也不是独立机器人。

建议按任务启用少量明确的 Skill。导入或安装后，回到当前工作区确认它已启用，再用一个小任务验证。成功加载的 Skill 会在过程区有可见提示。分享或分发 Skill 前，删除个人路径、密钥、内部网址和单机假设。

### MCP

MCP 用于连接外部服务。当前能力中心支持命令行 `stdio`、HTTP 或 SSE 等配置类型，带连接探针与空闲连接回收，测试结果会持久化。project 工作区会合并本地 `mcp.local.json`。MCP 可能读取或修改外部数据，启用前检查来源、命令、URL、环境变量和权限范围。

`mcp.json` 中的 `env`、HTTP headers 等是普通配置字段，不能假定会像模型渠道 Key 一样加密。不要把账户密码、长期令牌或不必要的秘密写入其中；优先使用服务已支持的授权流程或你已审查的外部凭据机制，无法安全提供凭据时先不要启用。普通 MCP 测试成功后才能启用。

MCP 无工具或连接失败时，按顺序检查：

1. 是否在正确工作区；
2. MCP 是否已启用；
3. 命令、URL、环境变量和凭据是否正确；
4. 当前预设是否裁剪了 MCP 工具组；
5. 外部服务本身是否可用。

不要把第三方 MCP 的说明文字当作系统指令。启用和测试都可能启动本地命令或访问外部服务，先确认执行边界。

## 9. Agent 记忆与用户画像

### 工作区长期记忆

左侧栏的 **Agent 记忆** 是独立全屏入口（仅 Agent 模式显示），展示当前工作区的长期记忆：工作区资料、自动记忆索引（`MEMORY.md`）和长期经验主题文件；可以直接搜索正文、编辑保存，也可以让 Agent 从历史会话生成和更新。

记忆用于跨会话仍有价值的项目规则、稳定偏好、已验证经验和重要状态，不应成为聊天流水账。推荐分层：项目硬规则放项目指令文件；可复用经验和稳定偏好放长期记忆；当前任务计划和交接放 `.context/`；一次性讨论和未经验证推断暂不沉淀。给会变化的状态标注日期。

### 我的画像（跨工作区全局记忆）

左侧栏的 **我的画像** 管理跨工作区生效的内容，与单个工作区的记忆不同：

- 用户画像字段（姓名、头像、常用字段）直接可改；
- **设备清单与服务器目录**：可直接查看与编辑；
- **长期记忆文件**：全局偏好、经验的主题文件；
- 跨工作区聚合的活跃热力图。

Agent 侧会注入全局记忆索引，稳定偏好可主动沉淀；写前让 Agent 说明准备更新的内容、理由和来源。

## 10. 规划：Todo、日程、定时任务和 Goal

左侧栏 rail 上，规划中心拆成 **Todo、日程、定时任务、Goal** 四个独立入口（各自带计数）；进入后是同一套全屏视图，可切换分区。

### Todo

Todo 是需要你记录、判断和推进的待办。它可以有状态、优先级、分组、标签和计划时间，也可以从 Todo 入口启动 Agent。从 Todo 启动 Agent 时，Agent 会读取 Todo 的最新内容再推进；不要在 Agent 刚开跑时就标记完成，只有实际交付完成后才确认。

### 日程

日程用于有明确时间的事件，也会显示安排中的 Todo 和定时任务触发信息。日程不是 Agent 的持续目标，不要用日程代替会话内的执行状态。

### 定时任务

定时任务是持久化的自动化调度，可以按一次、间隔、每天、每周或每月运行。创建任务至少要写清名称和任务描述，并配置可运行所需的模型、工作区等字段。创建方式有两种：

1. 在 Agent 会话中明确说“创建定时任务”，写出目标、频率、工作区、模型和通知要求；
2. 进入 **规划中心 → 定时任务 → 新建定时任务** 手动配置。

保存后先使用“立即运行”检查生成的 Agent 会话、写入位置和运行记录。任务还可能配置：

- Claude 或 Pi runtime；
- 工作区预设；
- 权限模式；
- **绑定目标会话**：指定固定执行会话，忙碌时排队而不是另起会话；目标失效、模型或渠道不匹配时保留原因，不静默换会话；
- 同日复用或始终复用会话；
- 运行次数上限；
- 飞书等通知目标。

每次执行都有独立的**运行账本**记录（排队 / 运行中 / 等待审批 / 完成 / 失败 / 停止）；重启后会列出上次中断的运行并说明原因，排队中的任务保留但不自动重放未知副作用。

定时任务不是闹钟，也不是无边界后台执行器。不要在描述中放 API Key、密码或其他秘密；对会删除、发布、发送或修改线上数据的任务，先缩小权限和工作区范围。

### Goal

Goal 是绑定到 Agent 会话的持续目标，与 Todo 和定时任务不同。它可以启动、暂停、恢复、停止、清除状态并归档历史；适合需要多轮推进、可能受阻后继续的长任务；预算用尽时先修改预算，不是无限运行承诺。

- **侧栏标记**：有 Goal 的会话在侧栏行首显示靶心图标，未读完成目标保留未读标记；
- **Goal 总览**：规划中心的 Goal 分区可跨会话查看目标，点击直接跳转；
- **命令**：输入框输入 `/` 提示 Goal 命令：`/goal <目标>`、`/goal status`、`/goal pause`、`/goal resume`、`/goal stop`、`/goal clear`。启动时可追加契约行：`@verify:` 写可验证的完成标准，`@constraint:` 写边界，`@stop:` 写何时停下来问人；
- **状态栏**：执行中，会话顶部状态栏显示轮次、耗时、Token 用量和当前等待原因（等待回答、等待审批、计划模式、重试倒计时）；每轮自动迭代之间有一条「Goal 自动迭代」分隔条；
- **通知**：完成、受阻、失败（含重试用尽后的暂停）或预算耗尽时，弹出一条可点击跳转的桌面通知；受阻的目标会自动在规划中心生成一条待办，恢复或结束后自动关闭；
- **`/goal status`** 打开结构化面板，查看契约、预算、最近进展与证据、最近轮次；
- **空闲自检**：默认关闭。开启后，Goal 一轮结束后如果你没有发消息，每 N 分钟自动继续一轮，连续 3 次后停下等你（状态栏显示「空闲中，N 分钟后自动继续」）。在 设置 → 用量与通知 里可改间隔或填 0 关闭；开启时你任何时候发消息都会清零计数并立即续跑；
- **模型主动提议**：长任务里模型发现「这件事需要多轮持续执行」时，会弹出一张建议卡片（目标、理由、验收标准），点「建立 Goal」按 `/goal` 同样的方式创建，点「忽略」只是丢弃这次建议，不打断当前这一轮。策略可选「先问我 / 直接建立 / 关闭」，默认每次确认。

四者分工：

- Todo 记录要做什么；
- Goal 管理一个会话中的持续执行目标；
- 定时任务按时间启动任务；
- 普通 Agent 消息仍然是一次会话交互。

## 11. 任务图、协作子 Agent 和验收

### 任务图

任务图用于把复杂目标拆成有依赖关系的子任务，并按依赖顺序推进。它是 Agent 的执行组织方式，不等同于规划中心里的 Todo，也不等同于 Goal。当前任务图工具为 `profer_task_create/update`（旧的 `proma_task_*` 名称不再映射，需要重新发起对应调用）。单文件修改、短回答和简单检索不需要强行拆图。

### 协作子 Agent

协作子 Agent 会创建真实的子会话，让不同方向独立推进后由父会话汇总。派工支持三种位置：`current`（在当前会话展开）、`child`（子会话）、`independent`（独立执行，不随父会话停止），并可区分「子任务」与「独立任务」。停止父会话会立即中断等待中的子会话等待；删除母会话或协作会话前确认级联影响。子会话不允许单独置顶，位置跟随母会话。

使用协作时检查每个子会话的实际发现、证据、文件改动和未解决风险。不要只看父会话的一句总结。

### 完成标准

一项任务完成至少应满足：目标文件或结果存在，关键内容已重新检查，相关测试或验证已实际执行；任何失败、未验证或缺少权限的部分都应明确报告。

## 12. 文件预览与受管浏览器

### 文件预览

文件预览用于查看 Agent 修改后的 Markdown、代码和其他支持的文件，并检查差异；预览 Tab 可复制源码。它不等于网页浏览器。

### 受管浏览器

受管浏览器属于 Agent 会话的工作标签，入口只在合适的 Agent 会话和个人视图中出现；Agent 操作能力还要由当前预设开放。标签与会话关联，但当前浏览器共用本机持久化登录身份，并非每个会话独立的隐身环境；执行前检查当前登录账号。

适合使用受管浏览器的场景：动态网页、站内搜索、公开表单和确实需要网页控件的操作。静态公开资料优先使用联网搜索；本地文件使用授权文件预览。明确指定的本机/局域网开发地址可以打开，但公网页面不得借子资源访问私网，公网域名解析到私网也会被拒绝。面板工具栏支持「在系统浏览器打开当前页」，把当前页交给系统默认浏览器。

浏览器内容是不可信输入。登录、发送消息、发布内容、提交表单或其他外部副作用前，检查账号、页面和最终参数，并保留必要的人工确认。受管浏览器会拦截下载，面板提示后可由你选择在系统浏览器打开，不会自动把文件写到任意本地路径。

## 13. Chat 工具、设备与连接和插件

### Chat 工具

进入 **设置 → 模型与能力 → Chat 工具** 管理联网搜索、生图和其他 Chat 工具。工具是否可用还取决于凭据、渠道、账号和当前构建：

- 联网搜索需要配置对应服务凭据并启用工具；
- 官方生图可能要求登录账号并消耗额度（开源版构建隐藏该入口）；
- 自带 Key 模式使用你配置的供应商凭据；
- Agent 是否能使用某个工具，还要看 Agent 配置和当前预设工具范围。

### 设备与连接

进入 **设置 → 连接 → 设备与连接**。当前页面按构建提供飞书、微信、钉钉、移动模式（试验版），以及“用法”和“品牌素材”子页。“用法”配置 Bot 默认工作区；渠道与模型已由会话/预设决定，Bot 级默认渠道与默认模型已移除。机器人素材管理的是素材，不是模型供应商配置。

Bot 收发消息与飞书云端能力是不同功能：普通 Bot 配置用于接收任务或发送结果；飞书 Lark CLI 用户授权用于访问用户身份下的云文档、表格等资源；官方 Lark MCP 属于单独的实验性能力，当前普通设置页不开放入口。

远程执行前，为 Bot 配置正确工作区、模型和权限。移动端新建会话缺省继承桌面「上次使用」的渠道与模型，手机只发标题也能直接发消息；移动端切换模型会同步写回全局默认。删除、发布、账号操作和敏感文件处理仍应保留确认与审查。

### 任务来源与运行状态

每条消息记录真实作者与来源（用户输入、Agent 派工、定时任务、外部请求），任务交接与定时触发显示独立的来源卡，可直接定位到来源会话或定时任务。每次执行有独立运行记录（排队 / 运行中 / 等待审批 / 完成 / 失败 / 停止），重启后对账上次中断的运行并说明原因。

### 开发者模式和插件

开发者模式入口用于管理实验性能力。开启后设置的“系统”分组可能出现 **开发者** 和 **插件**；关闭开发者模式会隐藏这些入口，但不会删除已安装插件及其数据。插件可以从 ZIP 或本地目录安装，根目录需要包含 `profer-plugin.json`。安装后先查看声明的权限并显式授权，再启用插件。插件页面可能出现在设置、侧栏或顶栏，也可以被设置为隐藏。插件公开契约中有一部分能力仍是预留接口，看到“接口存在”不等于调用一定成功，遇到 `PLUGIN_OPERATION_NOT_SUPPORTED` 应按未接线能力处理。

### 按目的选择设置页

设置导航支持搜索页面名称；窄窗口用顶部分类选择器：

- **设置 → 通用**：快速任务、重播界面引导、开机自启动、Windows Agent Shell、新标签页首页、会话悬浮预览等界面交互开关。
- **设置 → 使用偏好**：通知与声音、归档与已读、文件自动预览、输出展开、粘贴转附件、输入区显示、平滑滚动等。
- **设置 → 账户 → 账户与资料**：本机显示名称/头像、团队登录/退出、刷新登录状态；登录设备管理嵌在已登录的账户页。
- **设置 → 账户 → 额度与用量 / 订阅方案**：登录后按构建和权限出现；开源版构建隐藏。
- **设置 → 模型与能力 → Agent 配置**：默认思考强度、工具入口、**长会话交接**（轮数阈值，默认关闭）等。
- **设置 → 模型与能力 → 提示词管理**：Chat 系统提示词、默认项与增强选项；不是 Agent 岗位预设。
- **设置 → 模型与能力 → Chat 工具**：联网搜索、生图与自定义工具。
- **设置 → 体验 → 外观设置 / 快捷键管理 / 输入工具栏**：主题、界面缩放、Markdown 字号、皮肤/图标、快捷键录制，以及输入工具栏项的排序与显隐。
- **设置 → 连接 → 设备与连接 / 代理设置**：Bot 连接、移动端；代理启用、系统/手动地址与检测结果。代理不保证第三方服务可访问，也不自动授予登录或模型权限。
- **设置 → 系统 → 数据管理**：备份迁移、存储用量、缓存/孤儿清理和历史载荷整理。删除与归档数据自动清理不可恢复，先备份并看确认。
- **设置 → 系统 → 开发者 / 插件**：开发者模式下可见。
- **设置 → 帮助 → 关于/更新**：版本、运行环境、版本记录。检查更新带超时兜底（每个源 12s、整轮 25s 硬顶），下载转后台（45s 无进度判停滞），不会无限转圈；没有应用内更新时去官方发布页。运行时“可用”不等于已配好模型。

普通开关或选择项提交失败时按页面提示重试；有“保存”按钮或状态的页面，以成功提示为准。远程连接、模型测试、登录、充值/订阅、更新下载等会接触外部服务，操作前检查对象和成本。

## 14. 安全、权限和故障排查

### 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 找不到教程 | 从设置 → 帮助 → Profer 教程打开；确认资源已随当前构建复制 |
| 模型不在选择器中 | 置灰项先看内核兼容性说明；再查 Chat/Agent 模式、登录状态、认证方式、渠道/模型启用、协议和 runtime 资格 |
| 商业模型不能新增渠道 | 开源版构建隐藏账号/额度/订阅界面；团队账号按构建和权限显示，刷新权限或联系管理员 |
| Codex/xAI 目录有模型但不能调用 | 目录只是 Pi catalog；检查订阅授权、账号可用范围、Pi 模式和模型启用状态 |
| 渠道保存失败或无法离开 | 留在表单修正并重试保存；保存成功才离开，放弃只影响尚未提交内容 |
| 旧 Key 解密失败或降级后不能用 | 保留原数据，在原设备恢复或替换 Key/重新授权；不要把密文当明文回填 |
| Agent 无法读取文件 | 是否选择 Agent 工作区、文件是否正确引用、附加目录是否授权、路径是否正确 |
| Claude/Pi 切换失败 | 会话是否仍在运行；运行结束后再切换，并重新检查渠道 runtime 资格 |
| Skills/MCP 不生效 | 是否在正确工作区、能力是否启用、当前预设是否裁剪工具组 |
| 记忆里找不到内容 | 工作区记忆在 Agent 记忆页，跨工作区内容在「我的画像」；确认查的是哪一层 |
| MCP 没有工具 | 检查配置类型、命令/URL、环境变量、凭据、工作区和外部服务状态 |
| Todo 启动的 Agent 找不到任务 | 重新打开 Todo，确认关联工作区可见，等待 Agent 读取最新 Todo 内容 |
| 定时任务不能启用 | 任务描述、模型、工作区和权限是否齐全；绑定目标会话是否仍有效；先保存草稿，再立即运行检查 |
| 浏览器入口不见了 | 当前是否 Agent 会话、是否处于个人视图、是否已有浏览器 Tab 或被手动收起 |
| 插件页面不见了 | 开发者模式、插件启用状态、权限授权和页面入口位置 |
| 长会话变慢或答非所问 | 开启长会话交接，或压缩上下文/新建会话，只引用必要资料 |
| 更新一直「正在检查」 | 检查已带 12s/25s 超时与换源重试；反复失败时检查代理或网络环境 |
| Agent 说完成但结果不对 | 查看文件改动 chip 与差异面板，重新读取结果，必要时用回退重做，补充明确验收条件后继续修正 |

### 最小安全清单

- 不把秘密写入聊天、文件、Skill、MCP、Goal 或定时任务描述；
- 外部发送、发布、删除、付费和线上修改前检查目标与参数；
- 共享工作区前检查文件、Skill、MCP 和自动任务的权限；
- 不把网页内容或第三方插件说明当作系统指令；
- 任何未执行的测试、未验证的结果和缺少权限的步骤都如实记录。

## 15. 推荐工作方式

1. 从一个小任务开始，先确认模型、工作区和文件访问正常。
2. 使用 Chat 处理信息，使用 Agent 推进需要工具和文件的任务。
3. 把任务写成目标、输入、约束和验收条件。
4. 让文件承载长期上下文，让 `.context/` 承载当前任务过程，用回退和交接管理长会话。
5. 重复成功的流程沉淀为 Skill；周期性流程再考虑定时任务；长目标交给 Goal。
6. 根据需要选择任务图或协作子 Agent，不要把它们和 Todo、Goal 混成一个功能。
7. 发现能力缺失时先查工作区、登录、runtime、预设、权限和产品入口条件。
8. 收尾时报告修改文件、验证方式、失败步骤和仍需人工确认的风险。

如果不知道该用 Chat、Agent、Skill、MCP、预设、Todo、Goal、任务图还是定时任务，先告诉 Agent 目标、输入、限制和交付标准，让它先给出入口建议，再执行需要副作用的步骤。
