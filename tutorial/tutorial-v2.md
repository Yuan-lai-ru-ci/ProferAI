# Profer 用户指南

> 本文按当前 Profer 界面编写。功能和入口会持续更新；遇到本文与实际界面不一致时，请优先以当前界面、设置页和版本说明为准。

## 先完成一次真实任务

Profer 的核心不是“多聊几句”，而是把一件具体的事交给合适的工作模式完成。第一次使用时，建议按下面的顺序走一遍：

1. 打开 **设置 → 模型配置**，添加至少一个可用的模型渠道。
2. 在顶部切换到 **Agent**，选择或创建一个工作区。
3. 给 Agent 一个范围清晰、可以验证结果的任务。
4. 查看它读取了哪些文件、执行了哪些操作，必要时在权限请求处确认或拒绝。
5. 打开右侧文件面板或预览，检查最终文件和差异。

可以先用这个任务测试环境：

> 在当前工作区创建 `hello.md`，写一段项目介绍，包含项目名称、目标和技术栈。完成后告诉我文件路径，并检查文件内容是否存在。

如果只想问问题、改写文字或讨论方案，用 **Chat**；如果希望 Profer 读取文件、修改项目、执行命令或连续完成多个步骤，用 **Agent**。

教程入口有两个：设置中的 **体验 → Profer 教程**，以及应用内出现的教程推荐横幅。教程会在主区域以独立标签页打开，不会覆盖现有会话。

## 一、先认识界面

### Chat 和 Agent

**Chat** 是对话模式，适合问答、翻译、总结、润色、头脑风暴和轻量分析。它可以使用已启用的 Chat 工具，例如联网搜索或图片工具，但它的主要交互仍然是“输入问题，获得回答”。

**Agent** 是执行模式。Agent 会在工作区中使用文件读写、命令、搜索、预览、Skills、MCP 和其他产品工具，把目标拆成步骤并根据执行结果继续推进。它适合开发、整理资料、生成文档、批量处理文件和需要检查结果的长任务。

两种模式的会话列表、模型配置和部分设置相互独立。看到模型选择器里没有预期模型时，先检查当前模式、Agent 内核和渠道是否匹配。

### 左侧栏

左侧栏主要包含：

- Chat 和 Agent 会话列表；
- Agent 工作区及其会话；
- **规划中心**，管理待办、日程和自动任务；
- **Agent 技能**，管理 Skills、MCP、记忆和预设；
- 账户、工作区和设置入口。

一个工作区可以包含多个 Agent 会话。建议按任务拆分会话：一次会话围绕一个目标推进，长期项目的稳定信息写入工作区文件或记忆，而不是把所有事情堆在同一条对话里。

### 顶部标签和右侧面板

主区域顶部是标签栏，可以同时打开多个 Chat、Agent、文件预览和教程标签。Agent 标签右侧通常可以打开：

- **文件面板**：查看会话文件、工作区文件和改动；
- **受管浏览器**：让 Agent 在 Profer 内使用浏览器；
- **预览**：查看 Agent 修改后的 Markdown、代码或其他支持的文件。

文件面板和浏览器都按会话关联。切换会话后，先确认当前标签和右侧面板对应的是哪一个会话。

## 二、安装、登录和模型配置

### 首次启动

首次启动会进入欢迎和环境配置流程。Windows 上执行 Agent 命令通常需要可用的 **Git Bash 或 WSL**；按环境检测页的提示安装并重新检测。macOS 和 Linux 的运行环境要求不同，以当前安装包和环境检测结果为准。

如果你已经在其他设备使用过 Profer，可以在首次流程或设置中的迁移入口导入已有配置。导入前确认备份文件来自可信来源，并确认其中没有不希望带入当前设备的渠道或账户信息。

### 个人使用和团队账号

Profer 可以在本地工作区中使用，也可以登录团队账号：

- **个人工作区**：适合个人项目、笔记和本地文件，数据主要保存在本机。
- **团队工作区**：适合共享文件、共享记忆、团队 Skills 和协作项目，需要登录并加入团队。

是否登录不影响你使用本地功能。团队功能、订阅、额度、开放 API 和登录设备管理需要对应的账号权限。

### 配置模型渠道

进入 **设置 → 模型配置**，点击添加渠道，按供应商提供的信息填写：

1. 选择供应商或自定义协议类型；
2. 填写 API Key、Base URL 和渠道名称；
3. 拉取模型列表，或手动添加供应商没有返回的模型；
4. 保存后确认渠道已启用，并在输入框的模型选择器中选中模型。

不同渠道支持的协议和能力不同。最重要的区别是：

- **Claude Agent SDK 内核**通常需要 Anthropic 协议兼容的 Agent 渠道；
- **Pi Agent SDK 内核**可使用更多 OpenAI 兼容渠道，具体可用模型由当前渠道和模型注册信息决定；
- Chat 与 Agent 的可用渠道过滤规则不同；
- 思考档位、上下文窗口、工具调用和图片能力也可能由模型本身决定。

不要只看供应商名称判断兼容性。以当前模型选择器能否在 Chat 或 Agent 中显示、以及实际连接测试结果为准。遇到 `model not found`、模型列表为空或 Agent 无法启动时，先检查协议、Base URL、渠道开关和模型 ID。

API Key 等敏感配置由 Profer 按当前客户端的安全存储策略保存。不要把 Key 直接写进工作区文件、Skill、自动任务描述或发给不需要它的远程渠道。

## 三、如何使用 Chat

### 适合 Chat 的任务

Chat 适合以下场景：

- 解释概念、比较方案、翻译和润色；
- 根据你粘贴的内容做总结、提纲或改写；
- 对一段代码进行讨论，但不要求它直接修改项目；
- 使用联网搜索获取最新信息；
- 生成图片或编辑图片（需要在设置中启用并配置对应 Chat 工具）。

如果你希望模型直接修改本地文件、运行命令或持续检查一个项目，切换到 Agent 会更合适。

### 附件和引用

可以把文件拖到输入框，或通过附件按钮选择文件。引用内容时尽量说明文件用途、需要处理的范围和输出位置。大文件不要无目标地全部塞进对话，可以先告诉模型要查找的关键词、章节或表格。

输入框支持按当前界面提供的快捷引用入口选择文件、会话、Skill 或 MCP。菜单没有出现时，先确认当前会话已绑定工作区，并且对应能力已启用。

### Chat 工具

Chat 工具在 **设置 → Chat 工具** 中管理。常见工具包括联网搜索和 GPT Image；工具是否可用还取决于当前构建、渠道和配置。启用工具后，它会出现在 Chat 输入区的工具选择器或对应的工具菜单中。

## 四、如何使用 Agent

### 创建和选择工作区

Agent 的文件和能力都围绕工作区组织。创建或选择工作区后，工作区会有自己的文件、会话、Skills、MCP 和预设配置。

在 Agent 模式下：

1. 从顶部或侧栏选择工作区；
2. 点击新建会话；
3. 在输入框附近确认 Agent 内核、模型和权限模式；
4. 发送目标明确的任务。

没有选中有效工作区时，文件附件、路径引用和部分能力管理入口可能不可用。

### 选择 Agent 内核

Agent 工具栏中的内核选择器可以在 **Claude** 和 **Pi** 之间切换：

- **Claude**：使用 Claude Agent SDK，适合 Anthropic 兼容渠道和 Claude 生态能力；
- **Pi**：使用 Pi Agent SDK，适合支持 Pi 的模型渠道，并提供独立的执行链路。

内核切换会记住在当前会话中，并从下一轮消息开始生效。Agent 正在运行或后台等待时不能切换；先等待完成或停止当前运行。切换内核后，原内核的 SDK 会话不会直接混用，必要时按新内核重新开始上下文。

### 提示词怎么写

一个可靠的 Agent 请求至少包含四部分：

- **目标**：最终要得到什么；
- **输入**：使用哪些文件、目录、链接或上下文；
- **约束**：格式、范围、不能做的事和风险边界；
- **验收**：完成后检查什么、在哪里保存、如何汇报。

例如：

> 请读取工作区中的 `sales.xlsx` 和 `template.md`。先分析表格中各产品的销售额和成本，再把毛利率写入新的 `sales-report.md`。不要修改原始 Excel。如果数据缺失，列出缺失字段，不要自行猜测。完成后检查报告中的计算公式和文件路径。

不要只说“帮我处理一下这个项目”。如果任务包含删除、发布、发送消息、修改线上数据等高风险操作，明确要求 Agent 在执行前停下来确认。

### 权限、计划和执行过程

Agent 运行过程中可能请求文件、命令、浏览器或外部服务权限。根据任务风险选择适合的权限模式；不熟悉时保留确认步骤，并查看请求的工具、路径和参数。

复杂任务可能显示计划、任务节点、后台任务或协作子会话。不要只看最后一句总结，应检查关键工具调用和写入结果。Agent 如果被中断、权限被拒或某一步失败，可以直接说明失败原因并让它继续，也可以停止后重新组织任务。

Agent 工具栏还可能提供思考强度、压缩上下文、回退和消息队列等能力：

- **思考强度**越高通常越适合复杂任务，但会增加时间和消耗；
- **压缩上下文**适合长会话继续工作，压缩前先把重要决策写入文件；
- **回退**用于回到历史消息节点，具体是否同时恢复文件取决于当前 Agent 内核；
- **消息队列**可以在 Agent 工作时暂存下一条消息，自动发送开关按会话保存。

## 五、文件、工作区和上下文

### 三类文件来源

右侧文件面板通常会区分：

**会话文件**：只服务于当前 Agent 会话的附件和临时产物。适合一次性输入、草稿和中间结果。

**工作区文件**：当前工作区长期使用的共享上下文。适合项目代码、规范、模板、长期报告和可复用资料。

**附加文件或文件夹**：文件仍保留在电脑原位置，Profer 只把它作为当前工作区或会话的可访问目录。适合大型项目、Obsidian 笔记库、素材目录和已有代码仓库。

附加目录不会自动复制全部内容。让 Agent 访问外部目录前，确认目录范围和权限，避免把无关的私人文件一起暴露给会话。

### 文件引用和预览

使用 `@` 选择文件或目录时，引用的路径会随消息发送给 Agent。发送前检查引用标签，尤其是同名文件和多个附加目录同时存在的情况。

Agent 修改文件后，右侧预览可以查看内容；改动面板可以查看差异。建议让 Agent 在任务结尾列出：修改了哪些文件、没有修改哪些文件、如何验证结果。

### `.context` 工作台

Agent 会在工作区或会话目录的 `.context/` 下保存任务过程文件，常见名称包括：

- `todo.md`：任务进度；
- `plan/`：执行计划；
- `note.md`：调研和分析结论；
- `handoff.md`：交接信息；
- `automation/`：自动任务的跨运行记录。

这些文件不是垃圾文件。对长期项目，建议保留经过整理的结论，删除过时或重复内容。一次性任务的临时计划可以在任务结束后清理。

### 会话和上下文长度

长会话会增加模型处理成本，也会让旧信息干扰当前判断。建议：

- 一个会话围绕一个目标；
- 阶段完成后把决策和结果写入工作区文件；
- 新阶段新建会话，并引用必要的旧会话或文件；
- 大文件先搜索定位，再读取相关片段；
- 不要让 Agent 每轮重复读取不变的大段背景。

## 六、Agent 技能、MCP 和预设

### Agent 技能入口

左侧栏的 **Agent 技能** 是能力管理中心。进入后先选择工作区，再使用顶部标签切换：

- **Skills**：工作流手册和可复用的操作规范；
- **团队市场**：团队工作区中共享的 Skill 市场；
- **MCP**：外部服务连接配置；
- **记忆**：工作区长期记忆查看、搜索和维护；
- **预设**：岗位和能力组合配置。

Skills 与 MCP 是工作区级能力。切换工作区后，列表和启用状态也会变化。

### Skills 是什么

Skill 通常是一份 `SKILL.md` 和它的辅助资源，描述某类任务的流程、判断标准、输出格式和注意事项。它不是一个模型，也不是一个独立的聊天机器人；它是在 Agent 处理相关任务时提供的工作手册。

建议只保留真正会使用的 Skills。可以让 Agent 使用内置的 `find-skills` 帮你搜索候选 Skill，也可以从其他工作区导入。安装或导入后，在当前工作区确认它处于启用状态，再在 Agent 中使用。

如果某个工作流已经重复验证成功，可以让 Agent 使用 `skill-creator` 把流程整理成 Skill。先沉淀真实流程，再补充失败案例和验收标准，通常比一开始写一份很长的“万能 Skill”更可靠。

团队工作区还可以把适合团队复用的 Skill 发布到团队市场；发布前确认其中没有个人路径、密钥、内部网址或只适用于单台设备的假设。

### MCP 是什么

MCP 是 Agent 连接外部服务的协议。Profer 当前支持在能力中心配置外部 MCP 服务器，常见传输方式包括命令行 `stdio`、HTTP 和 SSE。MCP 可能拥有读取文档、访问项目管理系统、操作云服务等权限。

启用 MCP 前检查：

1. 服务器来源是否可信；
2. 命令、URL 和环境变量是否正确；
3. 它能读取和修改哪些数据；
4. 当前工作区是否真的需要它。

MCP 配置问题通常表现为服务器没有加载、工具列表为空或调用时报连接错误。先在 Agent 技能的 MCP 标签确认启用状态和配置，再检查外部服务本身。

### Agent 预设

预设可以理解为“岗位 + 工作环境”：把提示词段、推理强度、权限模式、Skills/MCP 范围以及部分产品工具裁剪组合成可复用配置。

Profer 内置三类预设：

- **标准**：完整的默认能力；
- **代码**：更强调最小改动、验证和代码任务闭环；
- **极简**：减少任务图、记忆和协作等重型能力，适合简单、短平快的任务。

预设是工作区级配置。你可以在 Agent 技能 → 预设中创建、复制、编辑、删除、设置默认值，也可以导入导出预设。当前会话通过工具栏的公文包入口切换预设；切换会在下一轮消息起完整生效，并记住在当前会话中。

自定义预设可以限制 Skills、MCP 或产品工具组。限制能力后，Agent 的对应工具和提示词会一起收敛；如果任务需要任务图、记忆、协作或自动任务，不要使用关闭了对应能力的预设。

不要把预设、Skill 和 MCP 混为一谈：Skill 是工作手册，MCP 是外部服务接口，预设是决定当前 Agent 以什么岗位和能力边界工作。
